# Установка ГОСТ Р сертификата и настройка КриптоПро CSP 5.0 на Ubuntu: мануал «из боли»

Решал нетривиальную задачу: завести **КриптоПро CSP с ГОСТ-сертификатами** на Linux (Ubuntu Server 22.04) без графической оболочки. Тот, кто хоть раз сталкивался с этим в российском сегменте, знает, как «весело» собирать рабочие команды по разным форумам и вики, ИИ тоже так себе помощник в этом деле.

Потратил кучу времени, во всем разобрался, стабилизировал... и тут задача скипнулась. Чтобы не пропало зря, делюсь готовой, проверенной на практике шпаргалкой — вдруг кому попадется такое счастье.

> **Проверялось на:** Ubuntu Server 22.04 LTS (amd64), КриптоПро CSP 5.0 R3.

---

## 1. Скачивание и распаковка дистрибутива

Необходимо скачать **КриптоПро CSP** с официального сайта. Выбираем последнюю сертифицированную версию на данный момент — **КриптоПро CSP 5.0 R3**.

Загружаем файл архива на сервер и выполняем распаковку:

```bash
gunzip linux-crypto.tgz
tar -xvf linux-crypto.tar
```

Переходим в распакованную папку. Там же находятся дополнительные модули, которые могут понадобиться для инсталляции (например, `stunnel`).

> **Обязательно проверить:** после распаковки откройте файл `linux-amd64.ini`. Версия должна быть не ниже `version=5.0.13000`.

---

## 2. Установка программы

Для запуска инсталляции выполните команду:

```bash
./install.sh
```

После успешной установки исполняемые файлы программы находятся по пути: `/opt/cprocsp/bin/amd64`

Первым делом убеждаемся, что бинарник вообще рабочий и смотрим список всех доступных команд:

```bash
/opt/cprocsp/bin/amd64/cryptcp --help
```

---

## 3. Установка корневых сертификатов и списков отзыва (CRL)

Необходимо установить корневой сертификат и список отозванных. Персональный сертификат устанавливается позже, вместе с привязкой закрытого ключа.

```bash
# Установка списка отозванных сертификатов (CRL)
/opt/cprocsp/bin/amd64/certmgr -inst -store mca -file /home/user/cert/ca.crl -crl

# Установка корневого сертификата
/opt/cprocsp/bin/amd64/certmgr -inst -store mRoot -file /home/user/cert/ca.cer
```

---

## 4. Ручное создание контейнера и перенос закрытого ключа

Закрытый ключ состоит из **6 файлов**: `header.key`, `masks.key`, `masks2.key`, `name.key`, `primary.key`, `primary2.key`.

Чтобы КриптоПро увидел ключ, создаем папку контейнера (имя придумываете сами, в примере — `MyKeys`), копируем туда файлы и выставляем права доступа:

```bash
sudo cp header.key masks.key masks2.key name.key primary.key primary2.key /var/opt/cprocsp/keys/$(whoami)/MyKeys/
sudo chown -R $(whoami):$(whoami) /var/opt/cprocsp/keys/$(whoami)/MyKeys
sudo chmod 600 /var/opt/cprocsp/keys/$(whoami)/MyKeys/*
```

Проверяем, что контейнер успешно создался, и смотрим его ID (FQCN):

```bash
/opt/cprocsp/bin/amd64/csptest -keyset -num_cont -verifycontext -fqcn
```

---

## 5. Установка и привязка личного сертификата к ключу

В выводе предыдущей команды находим номер (ID) контейнера и используем его для привязки личного сертификата.

> **Важно:** FQCN ниже — **вымышленный пример** для наглядности. Подставьте сюда **свой** идентификатор из вывода `csptest` на предыдущем шаге, иначе команда не сработает.

```bash
/opt/cprocsp/bin/amd64/certmgr -inst -store uMy -file ~/cert/personal_cert.cer -cont '\\.\HDIMAGE\a1b2c3d4-e5f6-7890-abcd-ef1234567890'
```

Для проверки успешной привязки вводим команду:

```bash
/opt/cprocsp/bin/amd64/certmgr -list -store uMy -v
```

**На что обратить внимание в выводе:**

- Строка `PrivateKey Link : Yes` означает, что к сертификату успешно привязался ключ и им можно подписывать.
- Строка `SHA1 Thumbprint : 0000000000000000000000000000000000000000` содержит уникальный номер (отпечаток), который используется для выполнения подписи.

## 6. Команды для просмотра хранилищ

```bash
# Просмотр корневых сертификатов (интересующий нас будет внизу списка)
/opt/cprocsp/bin/amd64/certmgr -list -store root

# Просмотр списка отозванных сертификатов
/opt/cprocsp/bin/amd64/certmgr -list -crl -store uCA
```

---

## 7. Тестирование работы (Сеть и Подпись)

```bash
# Проверка TLS-подключения к целевому серверу
# Указываем флаг -k, чтобы не проверялся список отозванных (актуально для тестовых стендов, если CRL протух)
/opt/cprocsp/bin/amd64/curl -v -k --cert 0000000000000000000000000000000000000000 https://your-server-url.ru

# Проверка создания электронной подписи
# Создаем тестовый файл и подписываем. При запросе вводим 'yes' (так как тестовый CRL может быть не валиден)
/opt/cprocsp/bin/amd64/cryptcp -sign -thumbprint 0000000000000000000000000000000000000000 -der ivanov.xml
```

После выполнения команды создания подписи рядом появится подписанный файл с расширением `ivanov.xml.sig`.

---

## 8. Управление лицензией КриптоПро

```bash
# Установка серийного номера лицензии
sudo /opt/cprocsp/sbin/amd64/cpconfig -license -set 00000-00000-00000-00000-00000

# Проверка текущего статуса лицензии
sudo /opt/cprocsp/sbin/amd64/cpconfig -license -view
```

>  **Про лицензию:** без установленного серийного номера КриптоПро CSP работает в ограниченном режиме (фактически — ознакомительный период). Для продакшена с ГОСТ-подписью лицензия обязательна, иначе подпись либо не создастся, либо будет невалидной с точки зрения проверяющей стороны.

---

## 9. Работа с цепочками сертификатов в формате P7B

```bash
# Установка цепочки корневых сертификатов (например, Альфа-Банк) в хранилище root
/opt/cprocsp/bin/amd64/certmgr -install -store uRoot -file AlfaBank.p7b

# Проверка (в списке должен появиться установленный сертификат)
/opt/cprocsp/bin/amd64/certmgr -list -store root -v

# Установка персонального сертификата из p7b в хранилище uMy
/opt/cprocsp/bin/amd64/certmgr -install -store uMy -file user_chain.p7b

# Проверка персонального сертификата
/opt/cprocsp/bin/amd64/certmgr -list -store uMy -v
```

---

## 10. Извлечение отдельного сертификата из хранилища

```bash
/opt/cprocsp/bin/amd64/certmgr -export -cert -store uMy -dest exported_cert.cer
```

После выполнения команды увидим список сертификатов в нашем хранилище `uMy`, выбираем номер сертификата, который нужен, и он сохранится.

Проверить выгруженный файл сертификата можно командой:

```bash
/opt/cprocsp/bin/amd64/certmgr -list -file exported_cert.cer
```

## 11. Если что-то пошло не так: где смотреть логи

КриптоПро CSP логирует свою работу в несколько мест. Если команда падает с невнятной ошибкой — идём смотреть сюда:

```bash
# Основной лог КриптоПро CSP (самое важное место при разборе ошибок)
/var/opt/cprocsp/logs/

# Системный журнал — сюда попадают ошибки загрузки модулей и служб
journalctl -xe | grep -i cprocsp
journalctl -u cprocsp* --no-pager -n 100

# Лог конкретной утилиты (например, cryptcp) с максимальной детализацией
/opt/cprocsp/bin/amd64/cryptcp --help
/opt/cprocsp/bin/amd64/cryptcp -sign -thumbprint <отпечаток> -der file.xml -errlog /tmp/cryptcp.log

# Проверка, что нужные службы КриптоПро вообще подняты
systemctl status cprocsp*
```

**Типовые ошибки и куда смотреть:**

| Ошибка | Вероятная причина | Что проверить |
|---|---|---|
| `Failed to acquire context` | Не поднята служба или нет прав на контейнер | `systemctl status cprocsp*`, права на `/var/opt/cprocsp/keys/` |
| `0x8009000D` | Контейнер не найден или битый ключ | Вывод `csptest -keyset -num_cont -verifycontext -fqcn` |
| `Certificate not found` | Сертификат не привязан к ключу | `certmgr -list -store uMy -v`, строка `PrivateKey Link` |
| CRL is expired | Протух список отзыва | Обновить `.crl` через `certmgr -inst -store mca ... -crl` |
| Подпись не проходит проверку на той стороне | Нет валидной лицензии | `cpconfig -license -view` |

---

## 12. Шпаргалка по путям и утилитам

- **Вызов справки со списком всех команд:** `/opt/cprocsp/bin/amd64/cryptcp --help`
- **Путь к контейнерам с приватными ключами:** `/var/opt/cprocsp/keys/$(whoami)/[имя_контейнера]`
- **Путь к логам:** `/var/opt/cprocsp/logs/`
- **Основные типы хранилищ:**
  - `-store root` — хранилище корневых сертификатов.
  - `-store uMy` — хранилище персональных сертификатов пользователя.
  - `-list -crl -store uCA` — хранилище промежуточных и отозванных сертификатов.
